决定进入中国市场之后，技术侧要做的事情可以列很长。但清单的价值不在"长"，而在**每项都能验证**。下面这份清单按五个阶段组织，你可以从任意阶段切入，但建议至少把"评估"完整做一遍——先测量，再动手。

## 阶段一：评估（Assess）

- [ ] 拿到大陆真实可达性数据：多地（北京/上海/广州方向）、多运营商的拨测基线
- [ ] 拿到大陆真实性能数据：分地区 TTFB / Core Web Vitals，而不是海外机房的监控
- [ ] 盘点第三方依赖在大陆的可达性：字体、统计、支付、地图、视频——每一个都是潜在的单点
- [ ] 合规差距清单：ICP 备案要求、数据与隐私要点、行业特殊要求

**怎么验证**：拨测报告 + RUM 数据 + 依赖可达性矩阵，三份材料齐了才算过。

## 阶段二：加速（Accelerate）

- [ ] DNS 策略：大陆解析落地到就近节点，TTL 允许快速切换
- [ ] CDN 策略：大陆有节点或预热路径；**HTML 也考虑边缘缓存**（这是最容易被漏掉的一项）
- [ ] 静态资源：指纹化文件名 + 长缓存；首屏资源瘦身（高延迟链路是放大器）
- [ ] 回源路径：确认哪些请求必须回源、回源走什么线路

**怎么验证**：大陆方向 TTFB 有量化改善（比如从秒级到几百毫秒以内），且缓存命中率可观测。

## 阶段三：托管（Host）

- [ ] 决定哪些部分需要本地存在：站点、API、数据，分别评估
- [ ] 域名策略：.cn 域名 vs 海外域名 + 备案主体的路径选择
- [ ] ICP 备案：主体、流程周期、未备案的替代方案（如港/新节点 + 边缘加速）都要有预案

**怎么验证**：备案状态可查、托管方案在大陆的实际延迟达标。

## 阶段四：分发（Distribute）

- [ ] 安卓渠道生态：主流应用商店清单与上架要求（大陆安卓分发高度碎片化，Google Play 不可用）
- [ ] 应用更新通道：版本分发、热更新、灰度的路径
- [ ] iOS 侧确认 App Store 中国区账号与合规要求

**怎么验证**：至少在目标渠道完成一次真实上架演练。

## 阶段五：运营（Operate）

- [ ] 持续监控：覆盖大陆真实用户体验的监控与告警，"慢"和"挂"都要有信号
- [ ] 变更流程：上线后如何确认大陆侧生效（边缘缓存的刷新策略）
- [ ] 应急预案：线路波动时的降级方案

**怎么验证**：一次真实故障或波动能在告警里被看到、被定位。
